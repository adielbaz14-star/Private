# נספח: צ'קליסט בדיקות ומסירה

מריצים במלואו לפני פגישת המסירה ([מודול 8](../08-dashboards-and-delivery.md)).
כלל הברזל: **באג שאתם מוצאים = מקצועיות; באג שהלקוח מוצא = סדק באמון.**

## א. מבנה ונתונים

- [ ] בתפריט מופיעים רק מודולים בשימוש, בסדר הגיוני
- [ ] כל שמות השדות בעברית תקינה, בלי שדות ברירת מחדל מיותרים על המסך
- [ ] כל ערך חוזר הוא Pick List (לא טקסט חופשי); הערכים ללא כפילויות ("פייסבוק"/"פייס")
- [ ] שדות חובה: שם + טלפון בלבד (אלא אם סוכם אחרת באפיון)
- [ ] הנתונים ההיסטוריים בפנים; De-duplicate הורץ — אפס כפילויות
- [ ] מדגם 10 רשומות אקראיות: עברית תקינה, טלפון לחיץ ומתחיל ב-0, מקור מולא
- [ ] כל רשומות הדמה מהבדיקות נמחקו (חפשו "בדיקה", "טסט", "דמה")

## ב. תהליך העסקאות

- [ ] שלבי ה-Pipeline תואמים למסמך האפיון המאושר, מנוסחים כעובדות
- [ ] לכל שלב מוגדר Probability הגיוני
- [ ] Closed Lost דורש/מציג שדה "סיבת אובדן" עם ערכים מוגדרים
- [ ] תצוגת קנבן עובדת וגרירה בין שלבים מתפקדת

## ג. מסע מלא מקצה לקצה (הבדיקה החשובה ביותר)

מריצים באמת, לא "בעיון":

- [ ] שליחת טופס מהאתר ← נוצר ליד עם מקור נכון
- [ ] מייל "ברוכים הבאים" אוטומטי הגיע (בדקו גם בספאם), עברית ושדות ממוזגים תקינים
- [ ] Convert ← נוצרו איש קשר (+חברה אם רלוונטי) + עסקה בשלב הנכון
- [ ] נקבעה פגישה מהכרטיס ← הופיעה ביומן המסונכרן
- [ ] נשלח מייל מהכרטיס ← נשמר ב-Timeline
- [ ] הופקה הצעת מחיר: לוגו, עברית, סכומים ומע"מ נכונים (או שנוהל ההצעה החלופי תועד)
- [ ] מחזור חתימה הושלם ← המסמך החתום נשמר בעסקה
- [ ] עסקה הועברה ל-Closed Won ← אוטומציית "אחרי סגירה" ירתה
- [ ] רשומות הבדיקה מהמסע הזה — נמחקו בסיום

## ד. משתמשים והרשאות

- [ ] כל משתמש התחבר בפועל לפחות פעם אחת
- [ ] לכל משתמש: התצוגות הנכונות, והוא לא רואה מה שאסור לו
- [ ] הרשאות מחיקה וייצוא — רק למנהלים
- [ ] אין משתמש משותף; לכל אדם חשבון משלו

## ה. אוטומציות ותקשורת

- [ ] כל Workflow Rule נבדק בהפעלה אמיתית — לא רק "מוגדר"
- [ ] התראת "ליד לא טופל" נבדקה (אפשר עם תנאי זמן מקוצר לבדיקה — והוחזר!)
- [ ] תבניות המייל נשלחו לכתובת אמיתית ונראות תקין גם בנייד
- [ ] חיבורי המייל והיומן פעילים לכל המשתמשים הרלוונטיים

## ו. דוחות ודשבורד

- [ ] כל דוח נפתח ומציג נתונים — ואין בו רשומות דמה
- [ ] כל מספר בדשבורד אומת מול המציאות (טווחי תאריכים!)
- [ ] הדשבורד נטען במסך אחד בלי גלילה, 4–6 רכיבים
- [ ] לבעל העסק יש גישה ישירה לדשבורד והוא מוגדר כדף הבית שלו

## ז. מובייל

- [ ] אפליקציית Zoho CRM הותקנה ונבדקה: חיפוש לקוח, חיוג מהכרטיס, הוספת Note
- [ ] המשתמשים שעובדים בשטח קיבלו הדרכת מובייל קצרה

## ח. מוכנות לפגישת המסירה

- [ ] דף עזר של עמוד אחד למשתמש — מוכן ומודפס/נשלח
- [ ] תרחיש ההדגמה החיה מוכן ותורגל (טופס ← ליד ← מייל ← קנבן ← דשבורד)
- [ ] סוכם מי משתתף בפגישה (בעל העסק + כל המשתמשים)
- [ ] רשימת "מה המערכת לא עושה בשלב זה" מוכנה לתיאום ציפיות
- [ ] הצעת ההמשך (ריטיינר/שלב ב') מוכנה להצגה בסוף חודש ההטמעה

## ט. אחרי המסירה (לא לשכוח)

- [ ] נקבעו מועדי הבקרה השבועיים לחודש ההטמעה
- [ ] מדדי האימוץ מוגדרים ([מודול 9](../09-selling-and-implementation.md), סעיף 5)
- [ ] תועדו צילומי מסך "לפני/אחרי" לתיק העבודות (באישור הלקוח)
