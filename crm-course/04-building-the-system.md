# מודול 4: בונים את מערכת המכירות בשטח

**זמן משוער:** 2–3 שעות

## מטרות למידה

1. להתאים שדות, מסכים ותצוגות לעסק האמיתי — ולהעלים כל מה שמיותר
2. לבנות את לב המערכת: תהליך עסקאות עם שלבים וסטטוסים הגיוניים
3. להגדיר משתמשים והרשאות בסיסיות כך שכל אחד רואה את מה שהוא צריך

## 1. הכלל החשוב ביותר: לוח עבודה נקי

מערכת מצליחה היא לא זו עם הכי הרבה יכולות — אלא זו ש**כיף לעבוד איתה**.
איש מכירות שנכנס בבוקר וצריך לגלול בין 40 שדות ריקים כדי למצוא טלפון —
יחזור לוואטסאפ תוך שבוע, והפרויקט שלכם ייכשל.

לכן סדר העבודה במודול הזה הוא קודם **להוריד** (מודולים ושדות מיותרים),
ורק אחר כך **להוסיף** (רק מה שהאפיון דורש).

## 2. ניקיון ראשון: מסתירים את מה שלא צריך

Setup ⚙ ← Customization ← **Modules and Fields**:

1. עברו על רשימת המודולים. כל מה שלא נדרש באפיון — **Unpublish/הסתרה**
   (לא מחיקה): לרוב Campaigns, Cases, Solutions, Vendors, Price Books,
   ולעסק B2C גם Accounts. אפשר להחזיר בכל רגע.
2. גררו את המודולים שנשארו לסדר הגיוני: Leads, Contacts, Deals, Tasks ראשונים.
3. תוצאה: תפריט עם 5–6 פריטים במקום 15. הלקוח שלכם כבר ירגיש את ההבדל.

## 3. שדות: השפה של העסק

Setup ← Customization ← Modules and Fields ← בחרו מודול ← **Layouts**.
עורך הגרירה מאפשר להוסיף, להסיר ולסדר שדות.

**אילו שדות מוסיפים?** רק מה שעונה על אחד משלושה:
עוזר להתקשר/למכור · נדרש לדוח שהמנהל ביקש · נדרש לאוטומציה עתידית.
כל השאר — החוצה.

סוגי השדות שתשתמשו בהם הכי הרבה:

| סוג שדה | מתי | דוגמה |
|----------|------|--------|
| **Pick List (רשימה)** | כל ערך שחוזר על עצמו — תמיד עדיף על טקסט חופשי | מקור ליד: פייסבוק/גוגל/המלצה |
| **Phone / Email** | פרטי קשר — מקבלים כפתור חיוג/שליחה | נייד |
| **Currency** | סכומים | תקציב משוער |
| **Date** | תאריכים שנרצה לסנן לפיהם | מועד אספקה מבוקש |
| **Checkbox** | כן/לא | "לקוח חוזר" |
| **Multi-Line** | טקסט חופשי ארוך — במשורה, אי אפשר לדווח עליו | רקע כללי |

טיפים קריטיים למתחילים:

- **שמות שדות בעברית** — זו המערכת של הלקוח, לא שלכם. "מקור הגעה" ולא "Lead Source".
- **Pick List במקום טקסט חופשי, תמיד כשאפשר.** "פייסבוק", "facebook" ו-"פייס"
  הם שלושה ערכים שונים בדוח — ודוח שבור זה לקוח מאוכזב.
- **שדות חובה (Required) במשורה:** רק שם + טלפון. כל שדה חובה נוסף = חיכוך
  שגורם לעובדים "לעגל פינות" עם נתונים מזויפים.
- סדרו את השדות בבלוקים הגיוניים: פרטי קשר למעלה, פרטי עסקה באמצע, פנימי למטה.

## 4. לב המערכת: תהליך העסקאות

Setup ← Customization ← Modules and Fields ← Deals ← Stage — מחליפים את
ברירת המחדל בשלבים שניסחתם במודול 3. לכל שלב מגדירים **Probability**
(סיכוי סגירה באחוזים) — ככה Zoho מחשבת תחזית הכנסות אוטומטית:

| שלב (דוגמה) | Probability |
|--------------|-------------|
| ליד חדש | 10% |
| נוצר קשר | 25% |
| פגישה התקיימה | 45% |
| הצעה נשלחה | 65% |
| במשא ומתן | 80% |
| נסגר בהצלחה (Closed Won) | 100% |
| לא נסגר (Closed Lost) | 0% |

- לשלב Closed Lost הוסיפו שדה Pick List "**סיבת אובדן**": יקר מדי / הלך
  למתחרה / לא רלוונטי / הפסיק לענות. במודול 8 זה יהפוך לדוח שמנהלים אוהבים.
- הציגו את העסקאות ב-**Kanban View** (לוח עמודות לפי שלב) — זו התצוגה
  שהופכת את המשפך למשהו שרואים בעין אחת, והיא ה"וואו" הראשון של כל לקוח.

**ולעסקים עם שני תהליכים שונים** (למשל: מכירת פרויקטים וגם שירות שנתי) —
Zoho תומכת בכמה Pipelines נפרדים לאותו מודול Deals. אל תדחסו שני תהליכים
לרשימת שלבים אחת.

## 5. תצוגות (Views): כל אחד רואה את העבודה שלו

**List View מסונן** הוא הכלי שהופך מאגר נתונים לתוכנית עבודה. בכל מודול,
ליד שם התצוגה — **+ Create View**, מגדירים סינון ובוחרים עמודות. תצוגות
שכל מערכת צריכה:

- **"הלידים שלי — לטיפול היום"**: Lead Owner = משתמש נוכחי, סטטוס ≠ סגור
- **"לידים שלא טופלו מעל 48 שעות"**: Created Time לפני יומיים + סטטוס "חדש" — תצוגת ההצלה של ההנהלה
- **"עסקאות פתוחות מעל 30 יום"**: עסקאות תקועות שצריך להעיר
- **"נסגרו החודש"**: מוטיבציה + בסיס לדוח

בחרו לכל תצוגה 5–6 עמודות בלבד: שם, טלפון, שלב, סכום, פעולה הבאה. לא יותר.

## 6. משתמשים והרשאות — בסיסי וזהיר

Setup ← Users and Control:

1. **Users** — הוסיפו כל עובד עם המייל שלו. אל תעבדו עם משתמש משותף אחד!
   כל הערך של CRM הוא לדעת *מי* עשה *מה*.
2. **Profiles** (מה מותר לעשות): התחילו עם שניים — Administrator (בעל העסק
   ואתם) ו-Standard (כל השאר). לרוב מורידים ל-Standard את הרשאות המחיקה
   והייצוא — עובד לא צריך יכולת למחוק לקוח או לקחת את כל המאגר.
3. **Roles** (מי רואה את מה): היררכיה פשוטה — מנהל מעל, נציגים מתחת. מנהל
   רואה הכל; האם נציג רואה לידים של נציג אחר? זו שאלה לבעל העסק מהאפיון.

**כלל למתחילים: אל תבנו מערך הרשאות מתוחכם.** עסק של 3–5 משתמשים צריך
"מנהל רואה הכל, עובדים רואים את שלהם" — לא יותר. מורכבות = תקלות.

## 7. בדיקת "יום בחיים" לפני שממשיכים

לפני שעוברים למודול הבא, הריצו את התרחיש המלא בעצמכם, כאילו אתם העובד:

1. נכנס ליד חדש (צרו אותו ידנית) — האם קל להזין אותו? פחות מדקה?
2. חזרתם אליו וקבעתם פגישה — יש איפה לרשום את זה? הסטטוס משקף?
3. המרתם לעסקה — היא נוחתת בשלב הנכון בקנבן?
4. הזזתם אותה בין שלבים בגרירה — ההיגיון עובד? שום שלב לא "סתום"?
5. בעל העסק נכנס — האם ב-30 שניות הוא מבין כמה עסקאות פתוחות ומה שוות?

כל צליעה בתרחיש = תיקון עכשיו, כשזה זול.

## תרגיל מעשי (2 שעות)

בנו את המערכת המלאה לעסק המלווה, לפי טבלת התרגום ממודול 3:

1. הסתירו מודולים מיותרים וסדרו את התפריט (סעיף 2)
2. התאימו שדות בעברית ל-Leads (אם יש) ול-Deals — כולל "מקור הגעה" כ-Pick List (סעיף 3)
3. בנו את ה-Pipeline עם Probability לכל שלב + שדה "סיבת אובדן" (סעיף 4)
4. צרו לפחות 3 תצוגות עבודה (סעיף 5)
5. הגדירו הרשאות: 2 פרופילים + היררכיית תפקידים פשוטה (סעיף 6)
6. הריצו בדיקת "יום בחיים" עם 5 רשומות דמה — ותקנו מה שצלע
