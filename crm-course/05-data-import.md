# מודול 5: יבוא נתונים וניקוי המערכת

**זמן משוער:** 90 דקות

## מטרות למידה

1. לאסוף את המידע ההיסטורי של העסק מכל המקומות שבהם הוא מתחבא
2. לנקות קובץ אקסל אמיתי ולהתאים אותו לשדות שבניתם — כולל בעזרת AI
3. לבצע Import בטוח ל-Zoho עם זיהוי כפילויות, ולדעת לתקן אם משהו השתבש

## 1. למה זה שלב קריטי (ולמה ממהרים בו הכי הרבה)

מערכת ריקה היא מערכת מתה. הרגע שבו הלקוח נכנס ורואה את **הלקוחות האמיתיים
שלו** בפנים — זה הרגע שבו המערכת הופכת מ"פרויקט" ל"כלי עבודה".

אבל: זבל שנכנס = זבל שיוצא. אם תייבאו 800 רשומות עם כפילויות וטלפונים
שבורים, הלקוח יאבד אמון במערכת ביום הראשון. לכן מנקים **לפני** שמייבאים —
לתקן בתוך אקסל קל פי עשרה מלתקן בתוך המערכת.

## 2. איפה מתחבא המידע של עסק ישראלי טיפוסי

מהאפיון (מודול 2) אתם כבר יודעים איפה. המקורות הנפוצים:

- קובץ/קבצי אקסל ("יש לי אחד מ-2023 ואחד חדש, הם קצת שונים")
- אנשי הקשר בטלפון של בעל העסק
- תוכנת חשבוניות (חשבונית ירוקה, iCount, Rivhit) — יש ייצוא לקוחות ל-CSV
- קבוצות וואטסאפ ותכתובות מייל (מכאן לא מייבאים — מפה מלקטים ידנית רק את החשובים)

**החלטה עם הלקוח — כמה היסטוריה מייבאים?** כלל אצבע: לקוחות פעילים ועסקאות
פתוחות — תמיד. לידים מתים מלפני שנתיים — לא. פחות זה יותר; מטרת המערכת
היא העתיד, לא הארכיון.

## 3. ניקוי הקובץ: העבודה שעושה את ההבדל

עובדים על עותק! שומרים את המקור בצד. עוברים על הקובץ ומתקנים:

| בעיה | דוגמה | תיקון |
|-------|--------|--------|
| שם מלא בעמודה אחת | "דנה כהן" | פיצול ל-First Name + Last Name |
| טלפונים בפורמטים שונים | 050-1234567 / 501234567+972 | פורמט אחיד 0501234567; להשלים 0 שנפל |
| ערכים לא אחידים | "פייסבוק", "פייס", "FB" | ליישר לערכי ה-Pick List שהגדרתם |
| עמודות שאין להן שדה | "הערה של רואה החשבון" | להחליט: שדה חדש? Notes? או לוותר |
| שורות ריקות/כותרות באמצע | סיכומי ביניים באקסל | למחוק |
| כפילויות באותו קובץ | דנה כהן מופיעה פעמיים | לאחד ידנית לפני היבוא |

**קיצור דרך עם AI:** הדביקו 20–30 שורות לדוגמה (בלי מידע רגיש מדי, ובאישור
הלקוח) ובקשו:

> זה קובץ לקוחות שאני מכין ליבוא ל-Zoho CRM. עמודות היעד שלי: שם פרטי,
> שם משפחה, טלפון (פורמט 05XXXXXXXX), אימייל, מקור הגעה (ערכים מותרים:
> פייסבוק/גוגל/המלצה/אחר). זהה בעיות בנתונים, הצע תיקונים, וכתוב לי
> את הטבלה המתוקנת. סמן שורות שדורשות הכרעה אנושית.

טכניקה: Excel עצמו — Remove Duplicates, סינון, ו-Find & Replace — סוגר את רוב השאר.

## 4. צ'קליסט חובה רגע לפני Import

- [ ] הקובץ שמור כ-CSV (UTF-8!) — אחרת העברית תהפוך לג'יבריש
- [ ] שורת כותרות אחת בלבד, בלי שורות ריקות ובלי תאים ממוזגים
- [ ] כל עמודה בקובץ ממופה לשדה קיים במערכת (הכנתם את השדות במודול 4)
- [ ] עמודת טלפון בפורמט אחיד — והיא מוגדרת כטקסט (שה-0 המוביל לא ייעלם!)
- [ ] ערכי Pick List בקובץ זהים אות-באות לערכים שהוגדרו במערכת
- [ ] הפרדתם קבצים לפי יעד: לידים לחוד, אנשי קשר לחוד, עסקאות פתוחות לחוד
- [ ] גיבוי של קובץ המקור שמור בצד

## 5. ה-Import עצמו — צעד אחר צעד

בתוך המודול הרלוונטי (למשל Contacts): כפתור ⋯ / Import ← **Import from File**.

1. העלו את ה-CSV.
2. **שלב המיפוי (Field Mapping):** Zoho מנחשת איזו עמודה הולכת לאיזה שדה —
   עברו ידנית על כל שורה ותקנו. עמודה לא ממופה = מידע שנזרק.
3. **טיפול בכפילויות (Handle Duplicates):** בחרו שדה מפתח — לאנשי קשר בישראל
   **טלפון נייד** עדיף על אימייל (לא לכולם יש מייל, אבל נייד יש). בחרו
   **Skip** (דלג על כפול) ביבוא ראשון — בטוח יותר מ-Overwrite.
4. אשרו והמתינו. Zoho תציג סיכום: כמה נוספו, כמה דולגו, כמה נכשלו —
   **הורידו את קובץ השגיאות** וטפלו בשורות שנפלו.

**רשת ביטחון למתחילים:** התחילו ביבוא ניסיון של 10 שורות בלבד. בדקו שהכל
נחת נכון — עברית תקינה, טלפונים עם 0, ערכי רשימות תקינים — ורק אז הריצו
את הקובץ המלא. טעות ב-10 רשומות מוחקים ביד; טעות ב-800 זה פרויקט.
ואם בכל זאת השתבש — Setup ← Data Administration ← Import History מאפשר
**Undo Import** ליבוא האחרון.

## 6. אחרי היבוא: בדיקת איכות וכללי ניקיון קבועים

בדיקה מדגמית של 10 רשומות אקראיות: השמות בעברית תקינים? הטלפון לחיץ
(כפתור חיוג)? מקור ההגעה מולא? ואז — Zoho מציעה **De-duplicate** ברמת
המערכת (⋯ בתוך המודול) שמאתרת כפילויות שנשארו ומאפשרת מיזוג (Merge).

קבעו עם הלקוח שני כללי ניקיון מהיום הראשון:

1. **אין רשומה בלי טלפון** — רשומה שאי אפשר להתקשר אליה לא שווה כלום.
2. **כפילות שמתגלה — ממזגים מיד**, לא "אחר כך".

## תרגיל מעשי (90 דקות)

1. **השיגו קובץ אמיתי** מהעסק המלווה (או בקשו מ-AI לייצר קובץ תרגול "מלוכלך"
   של 50 לקוחות ישראלים עם כל הבעיות מהטבלה בסעיף 3 — זה תרגול מצוין).
2. **נקו אותו** לפי סעיף 3, כולל שימוש ב-AI לזיהוי בעיות.
3. **עברו על צ'קליסט טרום-היבוא** סעיף-סעיף.
4. **הריצו יבוא ניסיון** של 10 שורות, בדקו, ואז יבוא מלא עם Skip לכפולים.
5. **בדיקת איכות:** מדגם 10 רשומות + הרצת De-duplicate.

## צ'קליסט סיום

- [ ] הנתונים ההיסטוריים החשובים של העסק בפנים — נקיים ובפורמט אחיד
- [ ] אפס כפילויות: בדקתי עם De-duplicate אחרי היבוא
- [ ] כל הטלפונים לחיצים ומתחילים ב-0; העברית תקינה בכל השדות
- [ ] קובץ המקור וקובץ השגיאות שמורים בצד
- [ ] סיכמתי עם הלקוח שני כללי ניקיון קבועים
